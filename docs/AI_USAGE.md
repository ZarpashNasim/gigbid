# AI usage
Tool: Claude (Claude Code session). Files: agent/*, rag/*, mcp_servers/portfolio, mcp_servers/marketplace, tests, docs.
Things it got wrong that were caught by tests:
1. The dead-letter wrapper caught LangGraph's interrupt signal (GraphBubbleUp), so approvals ended in `dead_letter`. Fixed by re-raising it.
2. The placeholder embedder used Python's per-process-randomised `hash()`, making retrieval non-deterministic. Fixed with crc32.
3. Picked MCP SDK 2.x, which removed `FastMCP`; pinned `mcp<2`.
4. First draft of the V8 corrective-RAG loop never incremented its retry counter inside the graph, so a weak job would have looped until LangGraph's recursion limit. Caught on review before it ran; fixed by advancing the counter in the retrieve node and bounding retries (test: `test_v8_terminates_and_abstains_when_nothing_supports_the_job`).
5. Test files with the same basename (`test_server.py`) in two packages broke pytest collection; renamed.
6. The LLM Matcher first counted a requirement as covered if retrieval returned *any* evidence for it, so every job looked like a fit. Found by running the rules-only dev baseline (bid-or-skip recall/precision were degenerate). Replaced by a support-grader with a strict lexical fallback; invented evidence ids are ignored (tests in `test_bid_graph.py`).
7. While refactoring `evals/runners/rag_eval.py` for multi-persona datasets, `load_groups` ended up calling itself recursively. Caught by the eval tests; rewritten.
8. **Circularity, disclosed**: I broadened the rule-based warning-signal detector (`agent/rules.py`) after reading the *dev* synthetic templates, so rule recall and the keyword intent baseline score high partly through shared template vocabulary. Holdout uses the same templates, so it does not remove this. Only the human audit on real posts (`gigdata/audit.py`) is a non-circular check; it has not been done yet. Before/after files are kept in `evals/results/decision_rules_{BEFORE,AFTER}_fixes_dev.json`.
9. Licences and columns of the Kaggle datasets could not be read from the development sandbox (network blocked), so they are recorded as UNVERIFIED in `data/sources.yaml` and the loader maps columns by alias with a `schema` command to verify against the real files.
10. The synthetic generator wrote files with `path.write_text()`, which on Windows translates `\n` to `\r\n` and encodes with the locale codepage, while the manifest hashed the untranslated UTF-8 bytes. So `test_manifest_hashes_match_files` passed on the Linux build sandbox but failed on Windows (Python 3.14). Fixed by writing `text.encode()` with `write_bytes` in `gigdata/synth.py`, making output byte-identical on every OS. No eval number is affected; the committed data was already LF and matched the manifest.
11. **GigSim is self-built, disclosed**: the `GigBid_Student_Starter_Kit_v0.1` does not contain the GigSim service — it only references "the provided GigSim service" and sets `GIGSIM_BASE_URL=http://localhost:8081`, `max_requests_per_minute: 20`. The instructor's GigSim was not available, so `gigsim/` is a self-built HTTP stand-in that serves `data/synthetic` with bearer auth, the 20/min limit and deterministic simulated client replies (`gigsim/README.md`). It is **not** the instructor's GigSim and is labelled as such everywhere; it exists so the system runs/demos/tests end-to-end. The official service can replace it by editing only `mcp_servers/marketplace/adapters/gigsim.py`. Config names/port were reconciled to the kit (`GIGSIM_BASE_URL`/`GIGSIM_API_TOKEN`, 8081; old `GIGSIM_URL`/`GIGSIM_API_KEY` kept as fallbacks) and the client-side rate limiter default lowered to the kit's 20/min. Integration tests: `tests/integration/test_gigsim.py`.
12. **Contaminated eval deleted, not reported**: a Groq free-tier all-real retrieval run (`rag_synth_dev_tiny_allreal`) fell back to the lexical reranker/grader on 48 of its calls (`llm_fallbacks {reranker:19, grader:29}`) because the tokens-per-minute limit exhausted the paced retries, so its numbers were mostly lexical. The file was deleted rather than cited. The clean embedder swap (hash→Ollama `nomic-embed-text`, 0 fallbacks) is saved in `evals/results/rag_synth_dev_subset_ollama.json`; a clean all-real reranker/grader number needs a local chat model (`ollama pull`) to escape the rate limit and is still pending.
13. **Signature extension (semantic support grader), tuned on dev, disclosed**: `SemanticSupportGrader` (`rag/stages.py`) replaces V8's strict-lexical grader with embedding cosine over the Ollama embedder. It triples V8 recall on the dev subset (0.156→0.490) while keeping abstention at 0.75 (`docs/EXTENSION.md`, `evals/results/rag_synth_dev_subset_v8_{lexical,semantic}.json`). The cosine threshold (0.60) was swept and chosen on **dev only** — holdout was not spent on it. Avoids the Groq rate limit entirely (embeddings, not chat), so it needs no API key; the reranker is still a lexical stand-in.
